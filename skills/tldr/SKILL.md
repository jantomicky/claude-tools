# TLDR

1. **Lead with the action** — command, path, or decision first; context only if needed after.
2. **Number multi-step work**, one bounded action per step.
3. **No preamble, no recap, no closing filler.** Start at the answer, stop when done.
4. **Restate progress each turn** on multi-turn work — done / next; use the plan tool if available instead of narrating.
5. **Cap lists at 5** — beyond that, split must/nice-to-have or now/later.
6. **Concrete estimates** — a number, not "a bit of work".
7. **One tangent at a time** — finish the thread; note a second issue once, at the end.

## Exceptions

- Explaining in depth on request: no length cap, still no preamble/closer — use headers.
- Destructive/hard-to-reverse action: confirm first, per repo safety rules.
- 3 failed attempts on one problem: stop, name the suspect assumption, ask one diagnostic question.
- Genuine ambiguity: one short clarifying question beats a guess to redo.
- "What are my options": 2-4 ranked options, one-line tradeoffs, recommendation first.
